# Decision 2: retained dual-reader reviewed transcription v1

## Statement-unit integration

For a fully verified DUAL_READER_REVIEWED_TRANSCRIPTION fact only, common
admission may derive currency and scale metadata claims from the verifier's
statement_unit_evidence. Its document SHA, statement page and sealed proof hash
must match that fact. Existing metadata values and recognized retained
native/OCR unit declarations must not contradict it. The supplied envelope
must replay consistently before derivation; the resulting envelope must pass
normal metadata qualification. Retained metadata and OCR text remain unchanged.
This supersedes the unit-text prohibition below only for currency and scale.
All other metadata, assurance, source, rights, time and use gates remain.

Owner-approved Decision 2 adds `DUAL_READER_REVIEWED_TRANSCRIPTION` as an
**offline research only** evidence tier. It has no Production, source promotion,
execution, exact-mode or PIT-backtest authority. Existing source, metadata,
issuer, assurance, currency/scale, period, scope, restatement, conflict and use
qualification remain prerequisites. Numerical agreement and accounting equations
alone establish none of those prerequisites.

## Bounded implementation

The lower owner is `stocklookup_core/evidence/dual_reader_transcription.py`.
It imports only the standard library. The common retained admission loader in
`official_document_qualification.py` reads its evidence; pure
`admit_official_financial_fact` independently replays the bytes using the existing
numeric, unit, scope and period recognizers. There is no second admission path.

This v1 qualifies current-column consolidated corporate income statement facts:
revenue/code 10, total profit after tax/code 60, and parent profit/code 61, with
printed `B02-DN/HN` or `B02a-DN/HN` form identity. It does not widen bank,
securities-company, balance-sheet, quarterly or comparative-column policy.
The already approved H1 bridge's `2025-H1` operand is allowed with its exact
period bounds and reviewed assurance. All other period admission rules persist.

Only two native-text requirements are replaced for a fully verified cell:
the contiguous value span's presence in retained page text, and the literal
value's presence in that text. The cited label, line code, metric/template,
document-bound citation and numeric normalization still must pass. Missing
metadata or assurance text cannot be supplied by this tier. Existing valid OCR
or native metadata/assurance proofs may be reused under their own contracts.
A fully verified dual-reader row may carry a registered `ocr_layout_proof`
reference. The retained owner then replays that hash-bound proof, including its
zero-native-candidate evidence, as document page text for metadata, assurance and
issuer literals only. Its identity and ticker/period/scope still apply. The OCR
row and statement-unit coordinate proofs are not run for that row and replace no
reason; any metadata/unit text failure stays. Without a valid dual reading the
row needs the OCR row proof as before.

## Retained source and files

Use the existing official evidence root and acquisition manifest. An overlay
contains `dual_reader_transcription = {relative_path, proof_sha256}`, plus the
explicit literal fields `issuer_literal`, `form_reference_literal`,
`statement_title_literal`, `current_period_label`, and `column_id`. The record
keeps the usual source page, raw label/value, document metadata and fact fields.
An inline success flag never qualifies anything.

The proof, two raw reader files and page image must resolve beneath
`<landing>/dual-reader-transcriptions/`; absolute paths, escapes and symlink
escapes are refused. Each read hashes the actual retained bytes again. No file
is repaired, normalized in place or generated by admission.

The manifest-selected source record must carry all three explicit rights fields:

- `rights_route: OWNER_APPROVED_OFFICIAL_ISSUER_RESEARCH_NOT_VIETSTOCK`
- `acquisition_route: INDEPENDENT_OFFICIAL_SOURCE`
- `rights_status: RESEARCH_AND_AI_READING_APPROVED`

It also carries exact `issuer_name` and `page_image_bindings`. Each image binding
is `{relative_path, sha256, source_page, printed_page}` and must equal the proof's
`page_image`. The document ID/hash must match the retained PDF, source record,
proof and both raw inputs. Image bindings are retained acquisition/render
provenance, not guessed from a filename or supplied only by the overlay.
Rights-unknown or restricted Vietstock-origin material stays blocked; byte
equivalence to an official PDF does not qualify its acquisition or rights.

## Byte-sealed proof and raw schema

The proof is a JSON object with:

- `contract_version: dual_reader_reviewed_transcription/v1`
- `document_sha256`, `document_id`, and the exact `page_image` binding above
- `readings`: exactly two `{relative_path, sha256, retained_at}` entries
- timezone-aware `comparison_started_at` and `admission_completed_at`

Each raw JSON record, retained before comparison, has:

- `contract_version: independent_image_reading/v1`
- `model_family`, `reader_id`, timezone-aware `recorded_at`
- `method: DIRECT_PAGE_IMAGE`, `independent_input: true`,
  `saw_other_reader_output: false`
- `input: {document_sha256, document_id, image_sha256, source_page, printed_page}`
- a literal `table` as specified below

Supported family aliases normalize GPT/Codex to `gpt`, Gemini to `gemini`, and
Claude to `claude`. Two accounts/products/versions of one family count as one.
Reader IDs must also differ. The second reader must receive clean image input;
it must not see the first output or expected values before retaining its record.
These independence assertions are retained operator/reader provenance, not a
claim that hashes can establish how a model was prompted.

`table` retains `issuer_literal`, `statement_title_literal`, `scope_literal`,
`form_reference_literal`, `currency_unit_literal`, `period_caption_literal`,
`columns`, and `rows`. Each column has `column_id`, `label_literal`,
`reporting_period`, and `role`. Each row has `line_code_literal`,
`row_label_literal`, and `cells`. Each cell has `column_id`,
`raw_value_literal`, `sign_literal` (`unsigned` or `parentheses`), and
`uncertainty` (an empty list for an eligible cell). Preserve all numeric columns
as read; this implementation selects one explicit current column.

The selected row/column and all shared literal headers must agree exactly, with
two literal-preserving bindings:

- A column `reporting_period` that is null, or byte-equal to the shared agreed
  `period_caption_literal`, means the caption states that column's period. Any
  other literal is kept verbatim, must agree between readers, and must itself be
  recognized as the fact period. The caption must still recognize as the fact
  period and the header must be an explicit current-period label.
- A leading outline enumerator printed in the numbering column (`3.`, `17.`,
  `17.1`, `18`) is split from the line item text before comparison. The
  remaining text must agree exactly and equal the row's `raw_row_label`. If both
  readers report an enumerator, the enumerators must also agree exactly. No
  letter, digit or accent is altered, and the line code is still compared exactly.

Duplicate row codes or cell/column identities, unreadable glyphs, unresolved
cell uncertainty, unknown family, unsupported current header, sign mismatch,
wrong form or row concept, implicit currency/scale, or missing bindings block
that fact. No digit is corrected and no equation is used to choose a reading.
Disagreement in another row does not globally block an issuer.

Raw artifacts in older/different schemas remain immutable and are not silently
treated as independent v1 readings. Their eligibility/mapping must be established
explicitly before use; postcomparison summaries are not substitute raw readings.

## Knowledge time and deterministic consumer

For each reader, source observation <= recording <= retention < comparison
start <= admission completion. Qualification rejects a claimed knowledge time
earlier than the maximum of both readings and admission completion. It does not
backdate, rewrite timestamps, or borrow a publication date for system knowledge.
The existing decision-cutoff check applies after this floor. Original evidence,
restatement and fact-conflict gates remain intact.

An admitted result retains the tier, family IDs, both raw hashes, proof hash,
knowledge floor, `OFFLINE_RESEARCH_ONLY`, and `pit_backtest_eligible: false`.
The existing H1 bridge calls common retained admission for each operand and
propagates these labels into each input's provenance. Its normal fact-local
conflict and cutoff checks still block dependent outputs.

## Annual B 02 - DN/HN bindings (Head Leader decision, 2026-11-24)

Three bounded rules. Nothing else is widened.

1. **Column label agreement.** Two readers' `label_literal` for the selected
   column agree if they are identical. They also agree if one equals the other
   followed by whitespace and a final token that is exactly the agreed table
   `currency_unit_literal` (e.g. `2025` vs `2025 VND` when the unit literal is
   `VND`). The shorter label is the agreed label. Any other difference is
   `DUAL_READER_LITERAL_DISAGREEMENT`. An applied normalization is recorded in
   the admission's `evidence_classification.literal_normalizations`.
2. **Yearless caption.** When the agreed caption recognizes no period, the
   selected column's agreed label must resolve one. Resolution uses
   `recognize_period`, or the label is a bare four-digit year. That period must
   equal the row's `reporting_period` and the qualified document-metadata period.
   The column role must be `current` in both readers. If neither the caption nor
   the column resolves, the fact is blocked. A caption that does recognize a
   period must still equal the fact period.
3. **Bare unit.** An agreed `currency_unit_literal` that is exactly `VND` (the
   whole literal) declares VND at scale 1, through one explicit mapping. The
   existing unit parser does not accept a bare `VND`. Every other literal keeps
   the existing parser handling, including `Triệu VND`, `Nghìn VND` and
   `Đơn vị: VND`.
4. **Form reference dash variants.** This rule applies only to the
   accounting-form identity match. U+2010, U+2011, U+2013 (en dash) and U+2014
   (em dash) are treated as ASCII `-`, and whitespace is ignored, as it already
   was. So `Mẫu số B 02 – DN/HN` matches `B02-DN/HN`.
   - Both readers' raw literals are untouched and must still agree exactly.
   - The match is recorded as `FORM_REFERENCE_DASH_VARIANT` in
     `literal_normalizations`.
   - No other form leniency applies: B 02 vs B 02a, DN/HN vs DN, and the
     TCTD/CTCK templates are unchanged.

## First real admission (HPG 2025-H1, 2026-11-24)

`tools/run_dual_reader_transcription_admission.py` seals one page without network
or model calls. It copies the PDF, page image, render metadata and both raw readings
byte-identically into the new retained subdirectory
`h1-2025-dual-reader-hpg-20261124`. Original files are only read. It writes one
manifest record: the original fields plus the three rights fields, `issuer_name`
and `page_image_bindings`. It also writes the sealed proof, with
`admission_completed_at` set once. It then replays codes 10/60/61 through
`admit_retained_financial_fact`. A rerun reuses only byte-identical files.

Focused synthetic tests in `tests/test_dual_reader_transcription.py` exercise
real retained-loader/pure-admission/H1-consumer integration and rejection paths.
Synthetic fixture success is local implementation evidence, not an actual
issuer admission. Real admission requires two eligible raw files, retained
official source/render bindings, rights and all existing qualification proofs.
