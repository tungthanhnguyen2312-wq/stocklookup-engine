# Owner Daily 16-GiB host and pipeline memory recovery

Owner-authorized `OWNER_DAILY_16GB_HOST_AND_PIPELINE_MEMORY_RECOVERY_V1` is a bounded
operational corrective. Authority effect: **NONE / MEMORY_AND_FAILURE_DIAGNOSTICS_ONLY**.
It introduces no provider, analytical policy, production entrypoint or evidence authority.

The existing [host preflight](owner_daily_host_preflight_contract.md), single writer,
immutable retention, release, calendar/session, runtime and completion gates remain binding.
No threshold, IID multiplier or scaling reference is relaxed by this corrective.

## Corrective boundaries

- Producer delivery borrows its already verified IID and projects one consumed row at a time.
  The public eager overlay API and all five delivery byte interfaces remain unchanged.
- Large registered and supplementary JSON inputs are parsed into their required graph record by record without
  retaining a full source Unicode string. Record mappings/lists and the existing Financial V2
  wrapper are decoded without dropping fields. Root/record-map duplicates and trailing data refuse.
  Small legacy artifacts retain their existing JSON reader. Source selection, frozen identities
  and coherence validation are unchanged.
- The Producer releases the independent planning input graph before the session operation
  resolves its frozen selection; current products reuse the operation-owned input graph.
- Action Center passes its already resolved same-session IID to the portfolio evaluator's
  existing optional input. Its full-graph loader also uses bounded decoding for large IID
  files. No second security-decision universe is parsed for the same evaluation.
- Scenario-binding identity hashes one record at a time through the unchanged field
  serializer, preserving NaN/default-string semantics and exact canonical identity bytes.
  No second sanitized bound universe or whole-universe serialization buffer is retained.
- Opportunity/decision context identity uses the existing strict record-bounded digest
  instead of whole-universe Unicode/UTF-8 buffers; identity exclusions remain unchanged.
- Workspace identity hashes one card at a time with its existing strict canonical
  serializer; all identity exclusions and nonfinite-value refusal remain unchanged.
- The independent periodic fundamental context is computed before Daily supplementary
  universes are loaded, so its source semantics/fact graphs do not overlap them. Its
  existing authority, period-alignment qualification and outputs are unchanged.
- Current-product serialization releases supplementary universes and intermediate
  opportunity/decision graphs after the final projection consumer; compact availability
  status and the optional case artifact remain for the unchanged outputs.
- Workspace pretty JSON is streamed to a temporary file with its exact original
  insertion-order/indent/newline bytes, then promoted through the unchanged atomic-copy
  API with bounded JSON validation. Validation failure preserves the previous target.
  The copy API still holds the UTF-8 file bytes; the larger Unicode buffer is avoided.
- Delivery self-verification hashes files in bounded blocks instead of a companion-sized buffer.
- The full-graph retained IID resolver uses the existing core bounded parser for large files.
  Owner M1 verification still hashes the complete loaded IID and verifies every delivery
  projection through its unchanged pinned launcher source. Header/contract/session/coverage,
  sealed operation/Brief/product/index, exact delivery scopes and all projected fields remain
  checked. The required graph remains resident; the whole-file Unicode decoding buffer does not.
- The velocity observer encodes each T0 record field once and feeds those bytes
  to both original record/snapshot hash domains. Both identities, all unconsumed
  content and the seven-axis projection remain verified by the unchanged frozen
  sorted-unique parser; no T0 bytes or authority semantics change.
- The existing failure hint names each failing dimension, observed/READY GiB and reason from
  the already generated observation; it takes no additional probe and grants no override.

The portfolio resolver keeps its existing public return contract. No evidence/result cache is trusted in
place of content verification. No process isolation or new resource framework is added.

## Qualification and limits

Retained-only experiments use the existing Windows Job guard, unchanged 7-GiB private-byte
ceiling, deadline and whole-tree reap. Expensive experiments are serialized. Outputs and
sanitized measurements belong outside production evidence. Current-scale measurements must
state which actual stages were exercised, output/content parity, source protection and any
missing stages; Producer-only measurements never certify whole-Daily capacity.

Local qualification, main integration and live acceptance are separate. A local checkpoint
does not authorize merge, production Daily, deployment, historical backfill or a successor.
The Owner relaunches the existing one-click Daily only after integration and a genuine fresh
READY observation. Historical T0 and capture knowledge cannot be reconstructed from later
inputs. The [capture contract](prospective_pit_capture_completeness_contract.md) and
[Monday contract](monday_live_readiness_closeout_contract.md) continue to govern missed sessions.


## October 26 retained qualification continuation

The 2,382,095,742-byte IID and a conservative full live set were retained through
observer build/write and both downstream full-velocity reads. This completed with
6.823 GiB peak private / 6.504 GiB peak RSS in 1,385.2 seconds under the existing
7-GiB/1,800-second lifetime guard. Native observer build/write took 1,150.2 seconds
under its unchanged 1,200-second guard. Velocity's 48,807 records, canonical identity
and raw output bytes match the original reference. All 30 original T0 files
(26,603,798,823 bytes, including the originally excluded source) retain their exact
before/after hashes; the same 29 sessions qualify. No excluded session is promoted.

The prior timeout combined native work with redundant serialization and independent
raw-source/parity audit work. Sharing encoded fields removes duplicate serialization;
independent raw-byte audits run in separate bounded phases, while native verification,
limits and final parity remain mandatory. A warm 100-record profile reduced encoding
CPU from 1.78 to 0.91 seconds and total CPU from 4.20 to 3.36 seconds.

Prior Producer, M1, Action Center and complete current-product measurements remain
applicable. The largest private peak remains 6.952 GiB, only about 48.8 MiB below the
diagnostic cap; the native observer has about 49.8 seconds below its deadline.
These are current-scale retained qualifications, not future-growth guarantees or
a host READY permit. Main integration, fresh host admission and real provider/session
acceptance remain Owner-controlled. No memory threshold or timeout is increased.
