# Owner Daily 16-GiB host and pipeline memory recovery

Owner-authorized `OWNER_DAILY_16GB_HOST_AND_PIPELINE_MEMORY_RECOVERY_V1` is a bounded
operational corrective. Authority effect: **NONE / MEMORY_AND_FAILURE_DIAGNOSTICS_ONLY**.
It introduces no provider, analytical policy, production entrypoint or evidence authority.

## IID runtime corrective — October 27

The October-26 Daily invocation at production `eaaf7c946d54b2f6b0ef41137b8dfa294e3dc77d`
passed host admission but failed with `DAILY_CAPACITY_MEMORY_LIMIT` while building IID.
This continues the same milestone; the earlier stage qualifications below do not
constitute successful acceptance of that Daily or authorize post-run publication.

The corrective reuses the existing record artifact loader for large pipeline inputs,
releases technical source graphs after their final projection, and releases financial
engine/semantic/readiness and feature-store graphs after their final consumers.
The caller's acquisition snapshot and the returned historical context stay intact.
IID consumes its private verified peer/divergence projection rows one at a time.
Historical content verification uses the existing strict record digest with its
original exclusions (including the original inclusion of `requested_at`).
Evaluated valuation verification also uses that digest with its original
`requested_at` exclusion, avoiding a whole-universe Unicode/UTF-8 hash buffer.
The atomic/streaming IID writer and working-view receipt are unchanged.

Windows capacity failures retain positive process/job allocation-limit events and
the available kernel peak process/job committed bytes through tree reaping. The
Owner result adds that diagnostic block and the last same-run child stage from
the bounded progress tail. These operational fields never enter artifact content
or identities. Missing limit notifications remain `UNKNOWN`; a low peak does not
disprove a denied allocation. Limits remain 7 GiB per process and 8 GiB per Job;
physical/commit reserves and containment refusal remain unchanged.

`tools/replay_iid_runtime_memory.py` exercises enrichment from copied full-scale
retained session inputs in a new experiment directory. It uses the production
capacity guard, real reserve probes, a finite experiment deadline, network/write
refusal, and optional exact retained corporate overlay and held acquisition graph.
It invokes neither Daily, T0 capture nor publication. Experiment telemetry and
source-byte manifests live outside production evidence.

The existing [host preflight](owner_daily_host_preflight_contract.md), single writer,
immutable retention, release, calendar/session, runtime and completion gates remain binding.
PR195 left thresholds unchanged. The final admission corrective below supersedes
only the physical READY band for its exact qualified source/input envelope.

## Corrective boundaries

- Producer delivery borrows its already verified IID and projects one consumed row at a time.
  The public eager overlay API and all five delivery byte interfaces remain unchanged.
- Large registered and supplementary JSON inputs are parsed into their required graph record by record without
  retaining a full source Unicode string. Record mappings/lists and the existing Financial V2
  wrapper are decoded without dropping fields. Root/record-map duplicates and trailing data refuse.
  Small legacy artifacts retain their existing JSON reader. Source selection, frozen identities
  and coherence validation are unchanged.
- The Producer releases the independent planning input graph before the session operation
  resolves its frozen selection; current products reuse the operation-owned input graph.
- Action Center passes its already resolved same-session IID to the portfolio evaluator's
  existing optional input. Its full-graph loader also uses bounded decoding for large IID
  files. No second security-decision universe is parsed for the same evaluation.
- Scenario-binding identity hashes one record at a time through the unchanged field
  serializer, preserving NaN/default-string semantics and exact canonical identity bytes.
  No second sanitized bound universe or whole-universe serialization buffer is retained.
- Opportunity/decision context identity uses the existing strict record-bounded digest
  instead of whole-universe Unicode/UTF-8 buffers; identity exclusions remain unchanged.
- Workspace identity hashes one card at a time with its existing strict canonical
  serializer; all identity exclusions and nonfinite-value refusal remain unchanged.
- The independent periodic fundamental context is computed before Daily supplementary
  universes are loaded, so its source semantics/fact graphs do not overlap them. Its
  existing authority, period-alignment qualification and outputs are unchanged.
- Current-product serialization releases supplementary universes and intermediate
  opportunity/decision graphs after the final projection consumer; compact availability
  status and the optional case artifact remain for the unchanged outputs.
- Workspace pretty JSON is streamed to a temporary file with its exact original
  insertion-order/indent/newline bytes, then promoted through the unchanged atomic-copy
  API with bounded JSON validation. Validation failure preserves the previous target.
  The copy API still holds the UTF-8 file bytes; the larger Unicode buffer is avoided.
- Delivery self-verification hashes files in bounded blocks instead of a companion-sized buffer.
- The full-graph retained IID resolver uses the existing core bounded parser for large files.
  Owner M1 verification still hashes the complete loaded IID and verifies every delivery
  projection through its unchanged pinned launcher source. Header/contract/session/coverage,
  sealed operation/Brief/product/index, exact delivery scopes and all projected fields remain
  checked. The required graph remains resident; the whole-file Unicode decoding buffer does not.
- The velocity observer encodes each T0 record field once and feeds those bytes
  to both original record/snapshot hash domains. Both identities, all unconsumed
  content and the seven-axis projection remain verified by the unchanged frozen
  sorted-unique parser; no T0 bytes or authority semantics change.
- The existing failure hint names each failing dimension, observed/READY GiB and reason from
  the already generated observation; it takes no additional probe and grants no override.

The portfolio resolver keeps its existing public return contract. No evidence/result cache is trusted in
place of content verification. No process isolation or new resource framework is added.

## Qualification and limits

Retained-only experiments use the existing Windows Job guard, unchanged 7-GiB private-byte
ceiling, deadline and whole-tree reap. Expensive experiments are serialized. Outputs and
sanitized measurements belong outside production evidence. Current-scale measurements must
state which actual stages were exercised, output/content parity, source protection and any
missing stages; Producer-only measurements never certify whole-Daily capacity.

Local qualification, main integration and live acceptance are separate. A local checkpoint
does not authorize merge, production Daily, deployment, historical backfill or a successor.
The Owner relaunches the existing one-click Daily only after integration and a genuine fresh
READY observation. Historical T0 and capture knowledge cannot be reconstructed from later
inputs. The [capture contract](prospective_pit_capture_completeness_contract.md) and
[Monday contract](monday_live_readiness_closeout_contract.md) continue to govern missed sessions.

## Launcher corrective — October 27 failed startup

The retained 07:46:27 attempt on `bff837a9` matched the capacity fingerprint,
but had 9,757,450,240 physical bytes available against 9,932,111,872 required:
166.5703125 MiB short. Its progress/log records show Owner PIDs 10740 and
4364 concurrently. The old relaunch used synchronous `subprocess.run`, so the
first interpreter remained resident throughout the successor's preflight.
The log records working sets, not private commit or parent PIDs; those facts
are established separately by bounded, harmless source-replay observations.

The existing PowerShell presentation host now waits for the old interpreter's
exit before starting the same executable/argv once more. Only exit 75 together
with a bounded, validated run-metadata request permits handoff. The request
cannot replace an executable, arguments or arbitrary environment variables.
Run origin, result/progress paths and the one presentation remain continuous;
the successor uses the existing journal/session/completion gates. A second
fast-forward, malformed/missing request or launch failure refuses success.
An interrupted handoff leaves the incomplete journal available for normal
recovery; it never invents completion. Direct Python callers use a small
sequential supervisor; the canonical one-click path uses its existing native
PowerShell host without another Python supervisor.

Integration must place the corrected PowerShell and Python sources in the
production checkout before starting its next process. An already running
pre-corrective PowerShell host cannot acquire the new supervisor by pulling
Python source. An updated entrypoint reached through that legacy synchronous
parent refuses before host admission (`LEGACY_SYNCHRONOUS_SUPERVISOR`) rather
than claiming the overlap has been removed. This source-only PR does not
perform that Owner-controlled integration or run Daily.

Publication-only imports now occur at their existing consumers. Intended-session
resolution calls the identical calendar leaf directly, with the same Vietnam
timezone conversion, instead of importing the producer graph. Calendar parity,
unchanged workflow bodies, canonical argv/guards, historical pins and source
boundaries are separately checked. The exact capacity receipt is refreshed for
these startup-only source changes; earlier finite stage qualifications are
reused, not represented as another whole-Daily qualification.

Two admission-path rehearsals with the production Python environment found
the old parent/child relationship through the Windows venv redirectors.
Each old Owner used about 294–295 MiB private commit and 65.7–66.0 MiB unique
resident memory. The corrected Owner used about 14.5 MiB private commit and
12.9 MiB unique resident memory. Including redirectors, removing overlap and
eager startup imports reduced private commit by 575.65–576.30 MiB and unique
resident RAM by **119.16–119.59 MiB**. Summed working-set differences are not
claimed as reclaimed physical memory because shared pages would be counted
twice. Host available-physical changes varied by 97.70–423.20 MiB while unrelated
host activity continued; these are noisy observations, not a repeatable permit.

**Admission remains unresolved.** Subtracting the conservative unique-resident
recovery from the original deficit leaves approximately **47.4 MiB**; this is a
counterfactual residual, not a fresh measurement of the old morning baseline.
A real native presentation/handoff rehearsal confirmed the old PID was gone,
with PowerShell itself retaining 39.07 MiB unique resident memory and the Owner
13.13 MiB. At that later observation only 3,244,044,288 physical bytes were
available (6,688,067,584 below READY), so this busy host was not READY. No apps
were terminated to improve these observations, and no production Daily ran.

The exact next corrective in this same incident is to qualify a presentation/
Owner process consolidation against at least the remaining 47.4-MiB resident
budget. Removing the measured PowerShell process alone provides at most
39.07 MiB unique resident recovery before replacement costs, so that change
alone must not be declared sufficient either. If the consolidated minimum
launcher still cannot close the measured gap, the 16-GiB host at that competing
load is outside the unchanged admission envelope. This record grants no merge,
production run, threshold reduction, containment change or successor milestone.

still visits every requested row with the unchanged serializer before returning;
subsequent reads inherit the IID store's byte-integrity checks. Delivery discovery
and Workspace consume those rows sequentially. Workspace retains only its original
compact scenario projection and reads each bound row once. Resident-artifact callers

evidence, policy or authority is introduced. Representative subset memory measurements
do not qualify a full-scale Producer or a smaller admission reservation.
